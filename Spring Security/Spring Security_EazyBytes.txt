https.cors(corsCustomizer -> corsCustomizer.configurationSource(new CorsConfigurationSource(){
	@Override
	public CorsConfiguration getCorsConfiguartion(HttpServletRequest request){
		CorsConfiguration config = new CorsConfiguration();
		config.setAllowedOrigins(Collections.singletonList("url"));
		config.setAllowedMethods(Collections.singletonList("*"));
		config.setAllowedHeaders(Collections.singletonList("*"));
		config.setExposedHeaders(Arrays.asList("Authorization")); // To expose header from backend to UI
		config.setMaxAge(3600L);  // To tell the browser remember this configuration for 1 hour. SO for 1 hour no need to perform the CORS check for multiple times.
		return config;
	}
}));

Browser will send a preflight request to the backend to know the CORS configuartion.  Backend should send Access-Control-Allow-Origin header which has the allowed orign configured in Spring as value.  Then only the actual API will be called.

CSRF:
*****
By default CSRF will be applied to POST, DELETE, PUT which are used to alter the data.

CSRF Token : Used to prevent CSRF attack. It will be unique per user session. It is also called as XSRF token. CSRF Token should be sent by the UI to the backend in each request  either in header or payload along with CSRF cookie by the browser.

Javascript can read the cookie from same domain not on another.

CsrfToken interface is used to create the CSRF Token by Spring. Use CookieCsrfTokenReposity class for storing CSRF Token in cookie is better than storing in session. 
CsrfFilter is responsible for validating the CsrfToken

To create custom CSRFCookieFilter:
---------------------------------- 
Create a class CSRFCookieFilter by extending OncePerRequestFilter and override doFilterInternal method.

Add this is SecurityConfig class
	http.csrf(csrfConfig -> csrfConfig.csrfTokenRepository(CookieCsrfTokenReposity.withHttpOnlyFalse()))
		.addFilterAfter(new CSRFCookieFilter(), BasicAuthenticationFilter.class)

Note:
-----
withHttpOnlyFalse :- js code also will be able read the cookie.  withHttpOnlyFalse refers to configuring a cookie with the HttpOnly attribute set to false.

Points:
^^^^^^^

*) HttpOnly is a flag you can set on cookies to tell browsers that the cookie should not be accessible via client-side scripts (like JavaScript). This is a security feature to help prevent cross-site scripting (XSS) attacks from stealing cookies.

*) If HttpOnly is true (the default and recommended for session cookies), the cookie cannot be accessed by JavaScript.

*) If withHttpOnlyFalse means setting HttpOnly to false, it allows client-side scripts to access the cookie.

*) Generally, avoid setting HttpOnly to false for sensitive cookies like session IDs or authentication tokens.

OAUTH2: Open Authorization
===========================

OAuth2 has grant types as below
*) Authorization Code
*) PKCE
*) Client Credentials
*) Device Code
*) Refresh Token
*) Implicit Flow(Legacy)
*) Password Grand(Legacy) 

1)AuthorizationCode - Flow will be by 2 types 
	*) To get the authorizaton code(clientId, response_type="code", scope(READ, WRITE etc), state(CSRF token to protect from CSRF attacks), redirect_uri) . Auth server will send code and the state with value which we send earlier
	*) Then to get access token(clientId , clientSecret , authcode, grant_type="authorization_code", redirect_uri). In both redirect_uri needs to be send.
	
2)Implict Grand Flow - (client_id, redirect_uri, scope, state, reponse_type="token"). ClientSecret is not involved since it is a get request. Here only one request to auth server to get the access token. It's not secure as the token value will be redirected in the url. In response we will get the access_token along with the state with value which we send earlier

3)Proof Key For Code Exchange(PKCE) -- Used for public clients(native and SPA) as public clients cannot securely store a Client Secret. Using code_verifier only the code_challenge(has value of code_verifier) is created by using the code_challenge_method.
	*) To get Authorization code (clientId, redirect_uri, scope, state, reponse_type="code", code_challenge, code_challenge_method=SH256). Authorization Server stores the code_challenge and sends the authorization code.
	*) To get access token(clientId , clientSecret , code, grant_type="authorization_code", code_verifier)code_challenge is the has representation of code_verifier. Auth Server verifies the code_challenge by the code_verifier which is send now and if valid it will send the access token. clientId & clientSecret are optional.
	
4)Password Grant Type -- Here user credentials(username & password) is shared. Used if Auth Server, Resource server and client belongs to same origanization as user credentials are shared. This grant type is deprecated.
	*) To get access token (client_id, client_secret, scope, grant_type="password" username="" , password="")
	
5) Client Credentials Grant Type :- Used when no end user involved, means when 2 backend application tries to communicate.
	*)  To get access token (client_id, client_secret, scope, grant_type="client_credentials"). We can use this flow if there are no user and ui involved.
	
6) Refreh Token Grant Flow: 
	*) When using AuthorizationCode & PKCE grant flow we will get access token and refresh token.
	*) When accessToken is expired refresh Token grant flow will be initiated using refresh token.
	*) client_id, client_secret, refresh_token, scope, grant_type ="refresh_token"
	*) offline_access scope is used to get a refresh token that never expires.

*) Auth server will use a private key and issue a token. The resourse server have to download the public key corresponding to the private key.
*) Using the public key the resourse server can validate the given digital signature of the token.

OpenID Connect:
---------------
OpenID connect is a protocol that sits on top of OAuth2.  OAUTH2 provides authorization via an access token containing scopes, OpenID connect provides authentication by introducing a new ID Token which contains information & claims for identity.

Here client receives access token & ID Token.

Implementing OAUTH2:
====================
Spring Security has inbuld support for Google, Okta, Facebook, Github as Enum class for  social login.


We can create login by 2 ways one by as below and another by giving details of client-id & client-secret of Authe server in application.properties file.
Steps:
------
1.) To implement we have to give http.oauth2Login() in SecurityConfig class.
2) Create a bean as below
	@Bean
	ClientRegistrationRepository clientRegistrationRepository(){
		ClientRegistration gitHub = clientRegistration():
		ClientRegistration faceBook = clientRegistration():
		return InMemoryClientRegistrationRepository(gitHub, facebook);
	}
3) Create a method as below for social login. For multiple social login we can create as many as blelow for each.

	private ClientRegistration clientRegistration(){
		return CommonOauth2Provider.GITHUB.getBuilder("github").clientId("clientId").clientSecret("clientSecret").build();
	}
	
For oauth2 the Authentication object will be OAuth2AuthenticationToken.

OAUTH2 & Keyclock:
==================

Have to use dependency spring-boot-starter-oauth2-resource-server as our application is the resource server.

ID token is used when grant type is of Authorization Flow. For Client Credentials Flow use access token.

For JWT Token:
--------------

1) Create a class for KeyclockRoleConverter by implementing Converter<Jwt(input), Collection<GrantedAuthority>(output)> for extracting the roles information from the token and converts that to SimpleGrantedAuthority.

2) Override convert method in Converter interface which accepts JWT token as input & return Collection<GrantedAuthority>
	public Collection<GrantedAuthority> convert(Jwt source){
	
	}

3) In SecurityFilterChain method of SecurityConfig do the below:
	JwtAuthenticationConverter jwtAuthConverter = new JwtAuthenticationConverter();
	jwtAuthConverter.setJwtGrantedAuthoritiesConverter(new KeyclockRoleConverter()); //The class created earlier
	
	http.oauth2ResourceServer(rsc -> rsc.jwt(jwtConfigurer -> jwtConfigurer.jwtAuthenticationConverter(jwtAuthConverter))); // rsc.jwt() To inform jwt is the format of our token. It can be opaque also based on our need.
	
4) In application.properties give the details of application created in Authentication Server(Keyclock)

5) spring.security.oauth2.resourceserver.jwt.jwt-set-uri = https://{authserverPath}/{application}/protocol/openid-connect/certs :- is the path where the public keys for validating the access token without connecting to the auth server.

https://{authserverPath}/{application}./well-known/openid-configuartion will give all the details of the Auth server


To download certs from keyclock
spring.security.oauth2.resourceserver.jwt.jwk-set-uri=${JWK_SET_URI:http://localhost:8180/realms/eazybankdev/protocol/openid-connect/certs}


For Opaque Token:
-----------------
1. Create a class for KeyclockOpaqueRoleConverter by implementing OpaqueTokenAuthenticationConverter() for extracting the roles information from the token and converts that to SimpleGrantedAuthority.

2. Override the method convert
	public Authentication convert(String introspectedToken, OAuth2AuthenticatedPrincipal authenticatedPrincipal){
		.......
		return new UsernamePasswordAuthenticationToken(name , null, roles)
	}
	
3. In application.properties add the below	
	*) spring.security.oauth2.resourceserver.opaque.introspection-uri =
	*) spring.security.oauth2.resourceserver.opaque.introspection-client-id =
	*) spring.security.oauth2.resourceserver.opaque.introspection-client-secret =
	
4) In SecurityFilterChain method in SecurityConfig class give the below
   http.oauth2ResourceServer(rsc -> rsc.opaqueToken(otc -> otc.authenticationConverter(new KeyclockOpaqueRoleConverter()).introspectionUri(introspectionUri).introspectionClientCredentials(clientId, clientSecret)));
   

Notes:

*) In scope if openid is not given then IdToken wont be there in response from auth server.
*) The certicatate from IAM will be download on the first request not on application startup.
*) For Opaque only we have to give introspection-uri , introspection-client-id &  introspection-client-secret. 
*) For JWT we have to give only jwt.jwk-set-uri.
*) In Keyclock Standard flow means Authorization Grand Type Flow
