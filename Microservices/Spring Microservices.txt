Gateway, Routing & Cross Cutting Concerns:
==========================================

EdgeServer or API Gateway: Server that sits on the edge of our microservice network and monitor all theincoming & outgoing requests.

Cross Cutting Concerns : logging, auditing, security & routing

Spring Cloud Gateway is used to create EdgeServer or API Gateway

Zuul is an alternative to Spring Cloud Gateway.

Spring Cloud Gateway is build on spring Reactor & Spring WebFlux provides circuit breaker integration, service discovery with Eureka, non blocking in nature has a superior performance compared to Zuul.

Adding Custom Filter:
######################
Creating Custom Filter by implementing GlobalFilter:
----------------------------------------------------

1) Create a class FilterName by implementing Global Filter by annotating @Component
2) Autowire FilterUtility filterUtility;
3) Override  public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) method.

Here Mono is for single Object. Flux is for collecton of objects. FilterUtility is util to get value or set value in headers.

Creating Custom Filter by using GlobalFilter Bean:
--------------------------------------------------

1) Create a class FilterName by annotating @Configuration
2) Autowire FilterUtility filterUtility;
3) Create a Bean for GlobalFilter
	@Bean
    public GlobalFilter postGlobalFilter() {
        return (exchange, chain) -> {
            return chain.filter(exchange).then(Mono.fromRunnable(() -> {
                HttpHeaders requestHeaders = exchange.getRequest().getHeaders();
                String correlationId = filterUtility.getCorrelationId(requestHeaders);
                logger.debug("Updated the correlation id to the outbound headers: {}", correlationId);
                exchange.getResponse().getHeaders().add(filterUtility.CORRELATION_ID, correlationId);
            }));
        };
    }

Making Microservices Resilient
==============================

Resilience4j is a fault tolerance library for Java applications.

Circuit Breaker Pattern is used to handle resilience.

States of Circuit Breaker Pattern:

CLOSED : Accepts all the requests
OPEN : If it sees a threshold requests are failing, then it will OPEN the circuit which will make requests fail fast.
HALF_OPEN : Allow few requests. Baed on the result it will either go to OPEN or CLOSED

Circuit Breaker Pattern can be implemented in Gateway server or individual microservices.

Implementing in Gateway Server:
------------------------------

1) Add dependency spring-cloud-starter-circuitbreaker-reactor-resilience4j
2) Add circuitBreaker Filter in method of class Main

	public RouteLocator eazyBankRouteConfig(RouteLocatorBuilder routeLocatorBuilder) {
		return routeLocatorBuilder.routes()
						.route(p -> p
								.path("/eazybank/accounts/**")
								.filters( f -> f.rewritePath("/eazybank/accounts/(?<segment>.*)","/${segment}")
										.addResponseHeader("X-Response-Time", LocalDateTime.now().toString())
										.circuitBreaker(config -> config.setName("accountsCircuitBreaker")  // For CircuitBreaker
												.setFallbackUri("forward:/contactSupport")))   // For fallback if any excepetion happens 
								.uri("lb://ACCOUNTS"))
					.route(p -> p
							.path("/eazybank/loans/**")
							.filters( f -> f.rewritePath("/eazybank/loans/(?<segment>.*)","/${segment}")
									.addResponseHeader("X-Response-Time", LocalDateTime.now().toString())
									.retry(retryConfig -> retryConfig.setRetries(3)
											.setMethods(HttpMethod.GET)
											.setBackoff(Duration.ofMillis(100),Duration.ofMillis(1000),2,true)))
							.uri("lb://LOANS"))
					.route(p -> p
							.path("/eazybank/cards/**")
							.filters( f -> f.rewritePath("/eazybank/cards/(?<segment>.*)","/${segment}")
									.addResponseHeader("X-Response-Time", LocalDateTime.now().toString())
									.requestRateLimiter(config -> config.setRateLimiter(redisRateLimiter())
											.setKeyResolver(userKeyResolver())))
							.uri("lb://CARDS")).build();
	}

3) Add below in application.properties

spring.resilience4j.circuitbreaker.configs.default.slidingWindowSize=10
spring.resilience4j.circuitbreaker.configs.default.permittedNumberOfCallsInHalfOpenState=2
spring.resilience4j.circuitbreaker.configs.default.failureRateThreshold=50   :- Its in percentage
spring.resilience4j.circuitbreaker.configs.default.waitDurationInOpenState=10000   :- Its milliseconds

Here default means for all services
if "accountsCircuitBreaker" is placed instead of default then its for account service.

BulkHead Pattern:
-----------------


The Resilience4j Aspects order is the following:
Retry ( CircuitBreaker ( RateLimiter ( TimeLimiter ( Bulkhead ( Function ) ) ) ) )

If you need a different order, you must use the functional chaining style instead of the Spring annotations style or explicitly set aspect order using the following properties:

- resilience4j.retry.retryAspectOrder
- resilience4j.circuitbreaker.circuitBreakerAspectOrder
- resilience4j.ratelimiter.rateLimiterAspectOrder
- resilience4j.timelimiter.timeLimiterAspectOrder
- resilience4j.bulkhead.bulkheadAspectOrder

	@Bean
    public SecurityWebFilterChain springSecurityFilterChain(ServerHttpSecurity serverHttpSecurity) {
        serverHttpSecurity.authorizeExchange(exchanges -> exchanges.pathMatchers(HttpMethod.GET).permitAll()
                .pathMatchers("/eazybank/accounts/**").hasRole("ACCOUNTS")
                .pathMatchers("/eazybank/cards/**").hasRole("CARDS")
                .pathMatchers("/eazybank/loans/**").hasRole("LOANS"))
                .oauth2ResourceServer(oAuth2ResourceServerSpec -> oAuth2ResourceServerSpec
                        .jwt(jwtSpec -> jwtSpec.jwtAuthenticationConverter(grantedAuthoritiesExtractor())));
        serverHttpSecurity.csrf(csrfSpec -> csrfSpec.disable());
        return serverHttpSecurity.build();
    }

EVENT DRIVEN MCROSERVICES:
==========================

Two Major Event Driven Models:
------------------------------
Publisher/Subscriber Model : Rabbit MQ
	New subscribers joining later will not have access to past events.
Event Streaming Model : Apache Kafka
	Allow clients to join at any time and recieve all past events. Events are written to a log in a sequential manner.  
		
RbbitMQ:
--------
Recognized for its utilization of AMQP(Advanced Message Queing Protocol) . It offers flexible asynchronous messaging, distributed deployment and comprehensive monitoring. 
Recent versions have incorporated event streaming functionalities into their feature set.

Producer(Publisher) :- Responsible for sending messages.
Consumer(Subscriber) :- Entity tasked with recieving messages.

Spring Cloud Function:
----------------------
Spring Cloud Function is a project in the Spring ecosystem that focuses on building applications around the idea of functions as the primary unit of business logic. Instead of tying your code to a specific runtime (like web controllers, messaging listeners, or batch jobs), Spring Cloud Function allows you to write simple functions (Function, Consumer, or Supplier) and then adapt them to different runtime environments.

Key Concepts:
~~~~~~~~~~~~~
*) Functional Programming Model
*) Decoupling Business Logic from Transport
	Your code doesn't need to care if the function is triggered by HTTP, messaging systems (Kafka, RabbitMQ), or cloud services (AWS Lambda, Azure Functions, GCP).
*) Serverless Ready
	Functions can be deployed directly to serverless platforms like AWS Lambda, Azure Functions, or Google Cloud Functions without modification.
*) Spring Integration
	Supports dependency injection, configuration, Spring Boot autoconfiguration, and the rest of the Spring ecosystem. You can also chain functions together and compose them dynamically.
